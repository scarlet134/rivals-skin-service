# RIVALS — готовые PNG tee для Discord (API v2)

Новый путь не собирает скин из публичной базы: клиент формирует **PNG только tee**,
а сервис принимает и отдаёт его **без изменения байтов**, без перекраски и изменения
размеров. Это серверная часть; новый экспортирующий модуль клиента устанавливается
отдельно. Само обновление сервиса ещё не меняет текущую карточку Discord.

## Обновление существующего Render-сервиса

Замените файлы в корне `scarlet134/rivals-skin-service` содержимым архива.
Не создавайте вложенную папку и не загружайте ZIP целиком.
Команды Render остаются прежними:

- Build: `npm ci --omit=dev`
- Start: `npm start`
- Node: `22`
- Root Directory: пустое поле
- Instance: существующий **Free**, ничего оплачивать не требуется.

После Commit changes дождитесь нового развёртывания. При подключении через
Public Git Repository автоматический деплой может не запускаться: используйте
**Manual Deploy → Deploy latest commit** на странице существующего сервиса.
Не создавайте второй сервис и не меняйте URL.

После запуска GET `/health` должен возвращать `"version":2,"upload_api":1`.
Старый `/skin.png?name=default` оставлен для совместимости с прежним клиентом.

## Новый API

`POST /api/tee`, Content-Type `image/png`, тело — сам PNG (не JSON и не multipart).

Требования: один валидный PNG 512×512 с альфа-каналом, не более 512 KiB.
Ответ: `{"ok":true,"image":"/tee/<sha256>.png","sha256":"...","expires_in":21600,"storage":"memory"}`.
`image` всегда относительный путь на этом же сервисе.

`GET /tee/<sha256>.png` отдаёт **исходный PNG байт-в-байт**.
Есть HEAD, ETag и Cache-Control. Имена файлов, ники, названия карт и игровые
адреса не требуются и не включаются в адрес изображения.

## Приватность и ограничения

- Картинка опубликована: её может открыть любой, у кого есть ссылка. Ссылка
  строится по SHA256 содержимого и не является паролем или авторизацией.
- Передавать нужно только изолированный tee. Не отправляйте скриншоты экрана,
  карты, чата, лица, документы или другие личные изображения.
- Сервис не умеет определять, что именно изображено на PNG. Ограничение «только tee»
  должно обеспечиваться экспортирующим кодом клиента, а не проверкой MIME.
- PNG хранятся **только в RAM**: максимум 96 изображений и 24 MiB, TTL до 6 часов.
  Старые могут быть вытеснены раньше. После перезапуска/засыпания Render память
  может быть очищена; клиент должен периодически перепубликовывать PNG.
- Free Render может засыпать; первый запрос после простоя бывает медленным.
  Это не гарантированное постоянное хранилище или SLA.
- При ошибке выгрузки/недоступности картинки клиенту нужен возврат к горе RIVALS,
  а не чужому или выдуманному скину.
- Endpoint загрузки публичный, без общего секретного токена в распространяемом
  клиенте. Защита от нагрузки: не больше 2 одновременно обрабатываемых загрузок,
  общий token bucket с burst 12 и пополнением 1 запрос/5 с, строгий размер и декодирование
  PNG, ограниченный кэш. Для большого публичного распространения потребуются
  отдельные меры против злоупотреблений и постоянное хранилище.
- Render и промежуточные прокси могут вести собственные журналы HTTP.

## Проверка

```
npm ci
npm test
npm start
```

Тесты проверяют старый API, проверку параметров, цвета старого рендера, обработку
ошибок, новый PNG endpoint, размеры, альфа-канал, SHA256, HEAD/ETag и **побайтовое
совпадение полученного изображения с отправленным**. Проверка на реальном Render
и визуальная сверка Discord выполняются после развёртывания/обновления клиента.

Старый renderer.mjs оставлен только ради совместимости. Новый `/api/tee` не
использует его для изменения загруженного PNG.
